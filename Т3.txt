"Единая система: Инвентарь, Владение, Хранилища и Торговля в симуляции мира
1. Фундаментальные принципы
Каждый предмет в мире — уникальный экземпляр с ID. Никаких «абстрактных» мечей в инвентаре.

Права собственности проверяет движок, а не языковая модель. Модель не может создать, переместить или продать предмет — только попросить ядро через чёткий API.

Всё находится в реальном мире. Предметы лежат в контейнерах (инвентарь, сундук, телега, магический карман) или на земле. Контейнеры — объекты с координатами или привязкой к сущностям.

Торговля — атомарный обмен между контейнерами, происходящий по правилам симуляции (расстояние, репутация, законы, налоги).

ГМ может создавать, редактировать и удалять любые хранилища и предметы, но через тот же строгий API, чтобы система оставалась целостной.

2. Предмет (ItemInstance) — единая модель данных
json
{
  "id": "uuid",
  "prototype_id": "iron_ring",
  "stack_size": 1,
  "container_id": "uuid_контейнера",
  "slot_index": 2,
  "state": "idle|equipped|in_trade|destroyed",
  "flags": {
    "quest_item": false,
    "bound_to_owner": null,
    "stolen": false,
    "magical": false,
    "fragile": false
  },
  "durability": 100,
  "custom_props": {},
  "created_at": "...",
  "last_moved_at": "..."
}
container_id определяет, где предмет находится прямо сейчас. Это может быть персонаж, сундук, телега, магический карман, пол в пещере.

Любое изменение владения — это смена container_id (и, возможно, owner_id самого контейнера).

3. Контейнеры — фундамент физического инвентаря
Контейнер – это сущность, которая содержит предметы и сама может находиться в мире (иметь координаты, владельца, замок).
Все контейнеры имеют:

json
{
  "id": "uuid",
  "type": "player_backpack|static_chest|mobile_cart|magical_pocket|faction_vault|ground_pile|...",
  "max_weight_kg": 100,
  "max_slots": 30,
  "owner_id": "character_or_faction_uuid",
  "location": {
    "world_coords": [x,y,z],
    "parent_entity": "player_123",   // если инвентарь персонажа
    "parent_container": null          // контейнеры не вкладываются (политика)
  },
  "lock_data": { "is_locked": false, "difficulty": 10, "trap": null },
  "physical_props": { "health": 200, "flammable": true }
}
Типы контейнеров
Инвентарь персонажа — player_backpack, привязан к Character. Имеет слоты: экипировка + рюкзак. Вес влияет на скорость/усталость.

Стационарные в мире — сундуки, бочки, тайники. Имеют координаты, могут быть заперты, разрушены. Содержимое выпадает на землю при разрушении.

Мобильные — телеги, вьючные животные. Имеют координаты (следуют за игроком), могут угнаны/сломаны. Контейнер телеги физически находится в мире, а не в интерфейсе.

Магические — «карманы», экстрадименсиональные пространства. Нет координат, привязаны к душе персонажа. Требуют заклинание для доступа, могут развеиваться.

Хранилища фракций — большие здания-склады с внутренними контейнерами (faction_vault). Принадлежат фракции, ACL по рангам. Физически находятся в закрытых локациях, требуют взлома/ключей.

Все контейнеры проверяются на доступ по единым правилам OwnershipService.

4. Симуляция мира и инвентарь
Связь инвентаря с миром двусторонняя:

4.1. Физическое присутствие
Предметы, лежащие в сундуке в подвале гильдии, реально там находятся. Игрок может их увидеть, подойти, попытаться взломать.

Если телега переворачивается — всё содержимое рассыпается по земле, создаются объекты ground_pile.

Дождь, огонь, магия области могут повредить/уничтожить контейнеры и их содержимое.

4.2. Экономическая симуляция
Каждый проданный торговцу предмет попадает в его инвентарь. Торговец может перепродать его, использовать в ремесле или отправить на другой рынок.

Динамические цены зависят от реального количества товаров в регионе. Ограбление склада шахтёров лишает регион металлов → цены на оружие взлетают.

Фракционные хранилища — источник ресурсов для строительства, войн, производства. Если украсть все припасы со склада — армия начнёт голодать.

4.3. Поведение NPC
NPC-торговцы имеют свои контейнеры-инвентари, которые физически лежат в их лавках. Ограбление лавки опустошает их запасы.

Стражники могут досмотреть инвентарь игрока на предмет краденого (проверка по флагу stolen).

Вьючные животные могут испугаться и убежать, унося контейнер с вещами.

4.4. Строительство и захват
Игроки могут строить свои сундуки, склады, ловушки. Всё это — контейнеры с их owner_id.

ГМ может создавать и настраивать любые контейнеры (в том числе фракционные, магические) через инструменты, задавая параметры.

5. Торговая система — транзакционный автомат
Торговля полностью опирается на систему контейнеров и владения.

5.1. Жизненный цикл сделки
Инициация:
Игрок говорит «Продаю перстень». LLM парсит намерение, определяет:

Продавец = текущий персонаж.

Предмет (из реального инвентаря, переданного модели в JSON).

Покупатель = ближайший торговец NPC (проверяется по локации и радиусам).
Модель не может выдумать предмет — она обязана выбрать из пришедшего списка.

Проверка возможности (сервер):

Предмет существует, container_id == player_backpack, state != bound, не quest_item, не stolen у этого торговца.

Торговец находится в радиусе, имеет достаточно золота в своём инвентаре (золото — тоже физический предмет или валюта на счету).

Формируется цена через EconomySim (база, торг, спрос).

Торг (опционально):
Модель отыгрывает диалог, но не меняет цену. При попытке предложить другую цену модель вызывает API: negotiate(trade_id, new_offer). Сервер либо принимает (если в пределах допустимого), либо отклоняет.

Подтверждение сделки:
Модель озвучивает финальную цену и запрашивает «Да/Нет». Подтверждение идёт через фиксированный диалог или кнопку.

Атомарное исполнение:
В одной транзакции:

Предмет переходит из инвентаря игрока в инвентарь торговца.

Золото (или валютные предметы) переходят от торговца к игроку.

Логируется событие trade_completed.
Если любое действие невозможно — транзакция откатывается.

Пост-обработка:
Торговец обновляет ассортимент, репутация сторон меняется. Экономика города фиксирует сделку. Если это был уникальный предмет, он может появиться на прилавке позже.

5.2. Защита от эксплойтов
Проверка владения ПЕРЕД исполнением: если предмет исчез (выброшен, переложен в другой контейнер за секунду) — сделка отменяется, ошибка.

Блокировка предмета: с момента инициации он в state: in_trade, не может быть перемещён.

Запрет продажи предметов, не прошедших проверку is_sellable(container_id, item_id).

Модель не может инициировать сделку с предметом, которого нет в пришедшем JSON-инвентаре.

6. ГМ-инструменты и управление миром
ГМ (администратор/мастер) может через API или UI:

Создать любой контейнер (сундук, телегу, зачарованный мешок) в любой точке мира или привязанный к персонажу.

Назначить владельца (owner_id, faction_id).

Задать предметы внутри контейнера, включая уникальные артефакты.

Мгновенно разрушить/запертить контейнер.

Создать торговую сделку вручную (например, для обучения).
Все команды ГМа используют те же методы ItemRegistry и TradeController, что и обычный геймплей, чтобы не обойти защиту.

7. Роль ИИ-ассистента в такой системе
Модель получает на вход жёстко заданный контекст:

json
{
  "player": {"id": "p1", "name": "Вор"},
  "inventory": [
    {"id": "i1", "name": "Перстень железный", "container": "backpack_slot_2", "flags":[]}
  ],
  "nearby_containers": [
    {"id": "chest_01", "type": "static_chest", "locked": true, "owner": "guild_mages"}
  ],
  "nearby_npcs": [
    {"id": "npc1", "name": "Торговец", "gold": 500}
  ]
}
Модель обязана:

Использовать эти данные, а не фантазировать.

При намерении продать — выбрать предмет из inventory (либо выдать ошибку, если игрок просит то, чего нет).

Передать команду initiate_trade с реальным item_id.

Озвучить результат, возвращённый сервером, без изменений.

Никогда не подтверждать сделку самостоятельно, не вызывая confirm_trade.

Промпт модели:

Ты — интерфейс к миру. Ты не имеешь доступа к базе предметов, не можешь менять их положение. Твоя задача — перевести слова игрока в строго определённые API-вызовы и честно озвучить ответ системы. Если игрок утверждает, что у него есть предмет, которого нет во входящих данных, ты обязан указать на это.

8. Практический пример: ограбление склада гильдии
Игроки проникают в здание склада (физическая симуляция проникновения).

Добираются до сундука фракции (faction_vault, owner: thieves_guild).

Вскрывают замок (навык взлома, потребление отмычек). Сервер меняет is_locked: false.

Открывают сундук — UI/модель показывают содержимое контейнера.

Игрок говорит «беру все свитки». Модель видит nearby_containers[0].items, передаёт команду move_items(source=chest, target=player_inventory, items=[sword_id]).

Сервер проверяет вместимость, отсутствие bound_to_owner, переносит предметы и ставит флаг stolen: true.

Фракция лишается свитков, экономика ощущает последствия (нет свитков в городе → подорожание).

9. Заключение
Мы получили систему, где:

Инвентарь персонажа — лишь один из множества контейнеров в мире.

Предметы физичны, имеют историю и лежат в конкретных местах.

Торговля — безопасная атомарная транзакция между контейнерами, не зависящая от честности LLM.

ГМ может настраивать всё, но не ломает защиту.

Игроки могут строить свои хранилища, грабить чужие, использовать магию — и всё это отражается на симуляции мира."
